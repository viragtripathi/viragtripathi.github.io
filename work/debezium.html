The missing connection

CockroachDB had changefeeds. Data teams also had an existing ecosystem of Kafka Connect and Debezium tooling. Connecting those two worlds meant making CockroachDB changes work within the interfaces teams already operated.

What I built

I wrote the CockroachDB connector from the first line of code and added CockroachDB support to the Debezium JDBC sink. The source streams changes out; the sink brings data in. Both were published on Confluent Hub.

The connector builds on an enriched changefeed envelope. I filed the original request in 2024 and worked with the product team; CockroachDB's CDC team delivered it in v25.2.

The engineering behind the integration

The work crossed two codebases and their contracts: CockroachDB's changefeed representation and Debezium's connector ecosystem. Getting the envelope supported in the database was a prerequisite to building the connector on top of it.

I also published examples so developers could move from reading the documentation to running the integration.

Try it yourself

Start with a working CDC pipeline. My Debezium examples include Docker Compose setups for replication between CockroachDB clusters, migrations from PostgreSQL and Oracle, and streaming changes to Iceberg or Neo4j.

Each demo includes a script that starts the services, drives sample changes, and checks the results. Start with the CockroachDB-to-CockroachDB demo, then adapt it to your own evaluation.

What changed

The Debezium project adopted the connector as an official integration, and it graduated out of incubating.

Teams can use CockroachDB through the Debezium ecosystem, with source code, documentation, examples, and packaged source and sink integrations available publicly.
